量潮：把「企业出题、学生接单」
做成一屏就能读懂的产品

本方案基于《量潮产品定位》对 C 端四个页面（任务大厅 / 任务库 / 个人中心 / 指南）重写界面文案并重构交互。 核心动作只有三件：标签自带说明、关键信息前置、每个页面只留一个主行动。

Design Principles
01标签自带说明

每个可能产生疑问的标签，右侧或下方跟一句 12 字内的说明。用户不必猜「难度」「岗位」「我的接单」到底是什么。

02决策信息优先

学生判断「接不接」只看四件事：报酬、周期、名额、截止时间。其余信息让位，浏览量和点赞量不参与决策，删掉。

03一屏一个主行动

任务大厅主行动是「认领」，任务库是「筛选」，「个人」是「处理待办」。同屏不放两个同等权重的按钮。

04状态先于内容

空、加载、失败三种状态与正常态一起设计。新用户第一次进来大概率看到的是空列表，而不是满屏卡片。

1
页面标题任务大厅

告诉用户「我在哪、这里能做什么」。取代原来无信息量的「首页」二字。

优化：标题语义化，与底部 tab 的「任务」形成上下呼应，不重复「首页」这种系统词。

2
消息通知红点提醒

承接验收结果、催办、企业回复三类通知，有未读才出现红点。

优化：原首页无通知入口，验收结果只能靠群消息；现改为站内闭环。

3
全局搜索占位符即说明

占位符写清可搜范围：任务、技能、企业。用户不用点开就知道能搜什么。

优化：原占位符只有「搜索任务」，把找企业的路径堵死了；补全三类对象。

4
AI 每日简报结构化 3 条 + 行动

AI 汇总昨日进度、今日待办、技能匹配任务，固定 3 条，超出折叠。

优化：原设计是一整段 AI 自动总结文字（且带「Hi, xxx」），读完不知道要干什么。现在每条都对应一个可执行动作，并给「去打卡 / 看推荐」两个出口。

5
岗位快捷筛选横向滑动

按职能一键切换，选中态填充蓝色；与任务库页的筛选条件双向同步。

优化：原首页没有筛选入口，找技术类任务必须跳去第二个 tab，多一次跳转。

6
分区标题排序依据 + 总数

「推荐任务」下加一行小字说明推荐逻辑，右侧给总数，让列表可预期。

优化：推荐必须说明依据，否则用户会怀疑是广告位；总数让「还有多少」可见。

7
任务卡片5 类信息 + 1 个行动

发布方与认证、标题（两行截断）、岗位/难度/形式标签、报酬、剩余名额与截止时间，右下角直接认领。

优化：① 卡片内直接认领，省掉一次进出详情页；② 删掉「浏览量 / 点赞量」，换成「剩余名额 / 截止时间」——前者是社交指标，后者才是接单依据；③ 报酬用橙色独立成列，扫读时第一眼可见。

8
底部导航3 项 · 图标 + 文字

任务 / 指南 / 个人，当前项蓝色高亮加粗，单层结构不设二级 tab。

优化：原 tab 只有文字、无图标、无选中态，点击后不知自己在哪里；补图标 + 颜色 + 字重三重反馈。

任务 指南 个人
功能标注共 6 处 · 悬停联动
1
页面标题任务库

与首页「任务大厅」区分：大厅是逛，任务库是查。标题不同，心智不同。

优化：原两个页面都叫「任务」，用户会以为掉进了同一个页面。

2
筛选维度标签标签旁写用途

「岗位」下补一句「决定做什么」，「难度」下补「决定能不能做」，把抽象词翻译成人话。

优化：原来只有「岗位」「难度」两个竖排字，新用户不知道这两行是筛选器还是导航。

3
筛选芯片选中态可见

选中项用蓝字 + 蓝框 + 白底，未选为浅灰底；默认提供「全部」随时可退回。筛选区整体吸顶，下滚时仍可改条件，改完自动回到列表首条。

优化：原设计是「技术 / 运营 / 产品」纯文字一排行，看不出哪个被选中，也无法取消选择——这是本次最严重的可用性问题。

4
更多筛选抽屉展开

周期、报酬、线上/线下三类条件收进右侧按钮，不占首屏；已选条件在按钮上以数字角标显示。

优化：学生真实决策还有「几天能做完」「给多少钱」，原设计只有职能和难度，筛完还是十几个任务。

5
结果条总数 + 排序

左侧给出「共 12 个任务 · 已选 3 个条件」，右侧可切换最新 / 报酬 / 临近截止。

优化：筛选后没有任何反馈，用户不确定是「没结果」还是「没刷新」；结果条是必要的心智锚点。

6
卡片复用同一套组件

与首页推荐列表使用完全相同的卡片与认领按钮；已认领的任务按钮变为「已认领 · 去打卡」。

优化：同一份数据在两处长得一样，认知成本归零；按钮文案随状态变化，避免重复认领。

任务 指南 个人
功能标注共 7 处 · 悬停联动
1
身份区头像 / 昵称 / ID

昵称后挂「学生认证」标，ID 支持长按复制（便于企业或助教核对），右侧直给资料完整度与补全入口。

优化：原设计只有「id」二字和一个头像，没有昵称、没有认证态；资料完整度是 B 端验收学生资质的依据，必须露出。

2
身份与院校决定可接任务范围

学生 / 企业在职两种身份，决定能看到哪些任务；院校信息用于校方统计。均为可修改项。

优化：原设计把「我的身份: 学生/企业」「我的学校:」做成两个胶囊，既没选中态也没说明用途，看起来像按钮又点不动。

3
数据概览接单 / 完成率 / 评分

三项核心数据：累计接单量、按期完成率、企业评分。这是企业筛人时最先看的三行。

优化：原页面没有任何数据，学生无法感知自己的积累，B 端也无法据此判断；数据同时是「数据变现」的产品基础。

4
我的接单带待办数量

副标题直接给「进行中 3 · 待验收 1」，不用点进去就知道有几件事在手上。

优化：原设计是两个无说明的灰色大方块，用户不知道点进去看到什么、也不知道里面有几条。

5
我的发布发布方视角

面向在校内发布任务的学生团队或教师，展示待处理与待验收数量。

优化：与「我的接单」并列同权重，形成「接单 / 发布」双向身份的对称结构。

6
能力标签实战数据生成

由完成的任务反推技能标签，已点亮为蓝色，未点亮置灰并提示「待点亮」，给出成长路径。

优化：对应产品定位里的「人才画像 / 能力雷达」，是学生留下来持续接单的核心激励，原页面完全没有。

7
设置列表按频率排序

消息通知、隐私与数据、帮助与反馈，每项右侧一句用途说明；退出登录放在最底部弱化。

优化：涉及学生个人信息与企业数据，隐私入口必须可达（合规要求），原设计缺失。

功能标注共 6 处 · 悬停联动
1
指南搜索按关键词直达

内容超过 4 篇后，入口式卡片就不够用了；搜索框保证「我知道问题叫什么，就不必翻」。首版可隐藏。

优化：原页面四个纯文字卡片，没有检索能力，也没有任何说明文字。

2
新手三步给路径，不给目录

把「怎么开始」拆成注册认证 → 认领任务 → 提交验收三步，每步一句说明加预计耗时。

优化：原页面只有四个入口，新用户看完仍然不知道第一步做什么——这是「指南」这类页面最常见的失效方式：只有目录，没有路径。

3
内容列表标题 + 一句说明

四个板块统一为「图标 + 标题 + 一句说明 + 箭头」，字号行高一致，扫读节奏稳定。

优化：原设计是「关于量潮」一张大竖卡 + 右侧两张小横卡，尺寸、圆角、内外边距全不一致，视觉层级混乱且暗示了不存在的优先级。

4
规则章程群规的正式化

把原本散在群公告里的长文本升级为可读页面：任务规范、信用分规则、违约处理，支持站内检索与分享。

优化：对应 Site 层「规则中枢」定位，原页面缺此项；这也是降低助教重复答疑成本的关键页面。

5
版本与更新底部固定

版本号、最近更新摘要、更新日志入口合为一条；并列一条「联系助教」，把兜底出口放在同一视线区。

优化：原「版本更新」是一个和内容卡片同等大小、同等样式的按钮，抢了主内容的注意力；改为弱化信息条。

6
底部导航与全局一致

指南页高亮「指南」，三个 tab 的字号、图标、间距与其余页面完全一致。

优化：四页共用同一个 tab 组件，避免各页微调导致的位置跳动。

Copywriting Rules

界面文案规范

四个页面通用，写文案时直接对照
类型写法示例
页面标题名词，2–4 字，说明「这是什么」任务大厅 / 任务库 / 个人 / 指南
功能标签名词短语，≤6 字，不用行业黑话岗位（不写「职类」）、难度（不写「等级」）
标签旁说明补一句「它用来干什么」，≤12 字岗位 · 决定做什么；难度 · 决定能不能做
按钮动词开头，≤5 字，说清点完发生什么一键认领 / 去打卡 / 提交验收（不写「确定」）
数据标签带单位与口径剩 2/5 名额；11-24 截止；按期完成率 92%
状态提示说明现状 + 给下一步暂无符合条件的任务 · 试试放宽难度
空状态一句话解释 + 一个出口按钮还没有接单 · 去任务大厅看看
注意 全站统一用「任务」而非混用「项目 / 订单 / 需求」；统一用「认领」而非「抢单 / 报名」；统一用「产出物」而非「作品 / 交付件」。同一概念一个词，是「简洁」最容易被忽略的一半。
State Design

三类必须设计的状态

当前线框图只画了「有内容」一种，另外三种才是新用户的高频路径
空状态

筛选无结果 / 未接单 / 无发布。文案结构：一句解释 + 一个出口。
暂无符合条件的任务 · 试试放宽难度

加载状态

任务列表用骨架屏，保持卡片高度一致，避免加载完成后页面跳动；顶部简报用一行「AI 正在生成…」占位。

失败状态

网络失败给重试；认领失败要说明原因（名额已满 / 资质不符 / 需先完善资料），不能只说「操作失败」。
